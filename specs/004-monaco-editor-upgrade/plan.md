# Implementation Plan: Robust Code Editor Upgrade (Monaco)

**Branch**: `004-monaco-editor-upgrade` | **Date**: 2026-05-11 | **Spec**: [spec.md](./spec.md)

## Summary

Replace the playground's CodeMirror editor with Monaco (`@monaco-editor/react`) to deliver TypeScript IntelliSense, inline type errors, hover types, go-to-definition, and import path autocomplete. One new npm package (`@monaco-editor/react`). All challenge types (`react-js`, `react-ts`, `node-ts`) continue working unchanged. CodeMirror is kept for interview views.

## Technical Context

**Language/Version**: TypeScript 5 / Next.js 16.2.4 / React 19
**Primary Dependencies**: `@monaco-editor/react` v4.x (new), `monaco-editor` (peer dep, pulled automatically)
**Storage**: N/A — no new state; Monaco model content mirrors existing `fileMap` Zustand state
**Testing**: Vitest 4 (no new unit tests needed — editor is DOM-heavy, manual smoke test suffices)
**Target Platform**: Browser, desktop viewport, sandboxed to playground pages only
**Performance Goals**: Zero impact on initial page load (Monaco is lazy-loaded); no input lag for challenges with ≤5 files
**Constraints**: No SSR — Monaco is client-only; existing `react-js`/`react-ts`/`node-ts` challenges must not regress; CodeMirror-based interview editor untouched
**Scale/Scope**: Small — 3 new files, 2 updated files, 1 new package

## Phase 0: Research

**Status**: Complete — see [research.md](./research.md)

Key findings:
- Monaco chosen over CodeMirror + TS worker: all required features built-in, zero assembly
- `@monaco-editor/react` v4.x: dynamic import with `ssr: false` in `'use client'` component
- `setEagerModelSync(true)` MUST be called before any model creation for cross-file IntelliSense
- URI format: `file:///challenge/<filename>` — all models share prefix so TS worker resolves relative imports
- Go-to-def: `registerEditorOpener` custom handler intercepts and calls `onFileNavigate`
- Import completions: custom `CompletionItemProvider` (TS service doesn't auto-resolve model paths)
- React types: fetched from unpkg on first load, cached, registered via `addExtraLib`
- Bundle: ~4-6MB gzipped, fully lazy (zero impact on initial page load)

## Implementation Tasks Overview

*(Detail in tasks.md once /speckit-tasks runs)*

1. **Install `@monaco-editor/react`** — `pnpm add @monaco-editor/react`
2. **Create `src/lib/editor/monaco-config.ts`** — `initMonacoDefaults`, `getEditorOptions`, `loadReactTypes`, theme definition
3. **Create `src/components/hub/playground/MonacoPlaygroundEditor.tsx`** — full Monaco editor with model management, go-to-def opener, import completion provider
4. **Update `PlaygroundShell.tsx`** — extend `Props` and `CodeEditor` prop type; forward `fileMap` + `onFileNavigate`
5. **Update `PlaygroundPage.tsx`** — switch dynamic import to `MonacoPlaygroundEditor`; pass `fileMap` + `onFileNavigate` to `PlaygroundShell`
6. **Run `pnpm build`** — verify zero TypeScript errors
7. **Manual smoke tests** — all three challenge types, go-to-def, import completion, JS regression
