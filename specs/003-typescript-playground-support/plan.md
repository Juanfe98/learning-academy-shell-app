# Implementation Plan: TypeScript Playground Support

**Branch**: `003-typescript-playground-support` | **Date**: 2026-05-11 | **Spec**: [spec.md](./spec.md)

## Summary

Extend the coding playground to support TypeScript (`.ts`) and TSX (`.tsx`) challenges. Two new environments: `react-ts` (typed React components with live preview) and `node-ts` (TypeScript scripting/OOP with console-only output). Transpilation uses the `typescript` Babel preset already bundled in `@babel/standalone` — zero new dependencies. The editor already handles TypeScript syntax highlighting via `@codemirror/lang-javascript` with `typescript: true`. Two demo challenges ship: a typed React counter (`react-ts`) and an OOP shapes exercise (`node-ts`).

## Phase 0: Research

**Status**: Complete — see [research.md](./research.md)

Key findings:
- `@babel/standalone` TypeScript preset is built-in. Add `'typescript'` to presets array based on file extension. Zero new dependencies.
- `getLanguageExtension` in `theme.ts` already returns `javascript({ jsx: true, typescript: true })` for `.ts`/`.tsx`. No editor changes needed.
- `buildExecSrcdoc` already exists for console-only execution. Use `buildPlaygroundSrcdoc` for `node-ts` too (simpler — same console postMessage type). Bundle entry for `node-ts` skips ReactDOM mount.
- `challenge.store.ts` requires no changes — `FileMap` schema is file-extension agnostic.
