# Implementation Plan: Academy Categories & Disney Collection

**Branch**: `008-categories-disney-collection` | **Date**: 2026-11-06 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/008-categories-disney-collection/spec.md`

## Summary

Two additive changes to the hub's discovery layer. First, every catalogue academy gains a required `category` (one of five fixed values) and the Learning Paths filter row becomes category pills, with the Home page academies section grouped under category headings. Second, a generic, data-driven **collection** record is introduced and rendered by one dynamic route (`/spaces/[slug]`), with "Disney" shipped as the first collection: its five codebase academies with progress, the Disney Staff Engineer job target card, a related-paths rail (Kubernetes, Datadog), and curated external links grouped by kind. A "Disney" entry is added to the sidebar. The progress store is untouched; all new logic is pure data plus two small pure helpers covered by Vitest.

## Technical Context

**Language/Version**: TypeScript 5 (`strict`), React 19.2.4, Next.js 16.2.4 App Router
**Primary Dependencies**: Existing only: Zustand persist store (read-only here), Framer Motion, lucide-react (`Castle` icon exists in the installed version). No new packages.
**Storage**: None added. Progress is read from the existing `se-hub-progress` localStorage store via the mounted-guard pattern.
**Testing**: Vitest 4, node environment, pure-function tests only (`src/lib/academy-categories.test.ts`, `src/lib/collections.test.ts`); `pnpm build` as the type gate; manual checklist in quickstart.md.
**Target Platform**: Desktop and mobile browser (hub web app). Sidebar entry must appear in both the desktop sidebar and the mobile drawer.
**Project Type**: Next.js App Router web application (single project).
**Performance Goals**: All grouping and filtering is in-memory over 19 academies; computed at module scope where data is static. No measurable cost.
**Constraints**: No change to `AcademyManifest` or `REGISTRY` (content layer); no change to the progress store shape; no new dependencies; `pnpm build`, `pnpm lint`, `pnpm test` must pass.
**Scale/Scope**: 19 catalogue academies, 1 collection, 3 job targets. 2 new lib files, 2 new test files, 1 new route, 1 new component, 5 modified files.

## Implementation approach

### Step 1 — Category taxonomy (foundation for US1, US5)
Create `src/lib/academy-categories.ts` with the `AcademyCategory` union, the ordered `ACADEMY_CATEGORIES` list with labels, and the pure `groupAcademiesByCategory()` helper that returns only non-empty groups in display order. Add `category: AcademyCategory` to `MockAcademy` and `HubAcademy`, then assign a category to all 19 entries per the spec table. Add the Vitest file. Checkpoint: `pnpm build` and `pnpm test` pass; nothing visible changes yet.

### Step 2 — Learning Paths category pills (US1)
In `paths/page.tsx` replace the `Filter` union and `FILTERS` constant with `"all" | AcademyCategory` and a module-scope `CATEGORY_FILTERS` list derived from `groupAcademiesByCategory(HUB_ACADEMIES)` (so zero-count categories never render). Filter the grid by `academy.category`. Search, header counts, empty state and animations remain as they are.

### Step 3 — Home grouped by category (US5)
In `(hub)/page.tsx` `PathsSection`, iterate `groupAcademiesByCategory(HUB_ACADEMIES)` and render a heading plus grid per group. Card stagger index restarts per group.

### Step 4 — Collection model (foundation for US2–US4)
Create `src/lib/collections.ts` with `CollectionLink`, `CollectionLinkGroup`, `Collection`, the `COLLECTIONS` array holding the Disney record, `findCollection()`, and the generic pure `resolveSlugs()` that returns matched items in requested order and skips unknown slugs. Add the Vitest file including a data-integrity test that every slug in every collection resolves against `HUB_ACADEMIES` / `JOB_TARGETS`.

### Step 5 — Collection route and view (US2, US3, US4)
Create `src/app/(hub)/spaces/[slug]/page.tsx` and `src/components/hub/collections/CollectionView.tsx`. The page resolves data; the view renders header, academies grid (PathCard + progress with mounted guard), job target cards, related-paths rail, and link groups, each section hidden when empty.

### Step 6 — Sidebar entry (US2)
Add the `Disney` item (`/spaces/disney`, `Castle` icon, `matchPrefix: true`) directly after Learning Paths in `navItems`. Desktop and mobile both consume `navItems`, so one change covers both.

### Step 7 — Verify
`pnpm test`, `pnpm lint`, `pnpm build`, then the manual checklist in quickstart.md.
